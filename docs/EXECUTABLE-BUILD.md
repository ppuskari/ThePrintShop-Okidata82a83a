# Executable runtime build

## Current status

R8 is a reproducible executable build, not only a source patch. The Windows
build assembles the historical Print Shop controls and the current OkiGraph
versions with Merlin32, verifies the matching production runtime, and installs
the modified overlays into a runnable DOS disk.

Validated R8 output:

```
PrintShop-Okidata82a83a-OkiGraphI.dsk
143360 bytes
SHA256 fc0c54c0d457845e27cc259429e36ce1604684df6bb22eabbe63f270669de92b
```

## Proven runtime mapping

Untouched Merlin32 control builds were compared against
`ColorPrintShop.DSK`.

```

MENUS7.S     MENUS7   $6300  3014    86d7fa76bfd693d461aa9085e3612253837e7f5f02a6027581beef3284c5355f
GCDRAW.S     DRAW1    $7800  2737    cfa548eb4f950156c14639372f2681edbaa810e86f0945d73c24e0304e436353
```

All three shipped payloads are byte-for-byte identical to their untouched
control builds. In particular, this proves that the production filename
`DRAW1` is the executable generated by historical `GCDRAW.S`.

## One-command Windows build

From the repository root:

```powershell
.\scripts\Build-RuntimeDisk.ps1
```

The script:

1. locates Merlin32 or downloads pinned v1.1.10;
2. retrieves the 1987-01-26 source snapshot;
3. prepares untouched and patched PRCOMS, MENUS7, and GCDRAW sources;
4. assembles all control/patched overlays;
5. verifies exact control and R8 hashes;
6. downloads or accepts a local `ColorPrintShop.DSK`;
7. verifies runtime PRCOMS, MENUS7, and DRAW1 against the untouched controls;
8. replaces only those three DOS binary payloads through their existing T/S
   chains; and
9. rereads every modified overlay and verifies its load address, length, and
   bytes.

Output:

```
build-runtime\PrintShop-Okidata82a83a-OkiGraphI.dsk
```

A local base can be supplied:

```powershell
.\scripts\Build-RuntimeDisk.ps1 -BaseDisk C:\path\to\ColorPrintShop.DSK
```

The builder refuses a base whose verified control overlays do not match.

## R8 hardware purpose

R7 hardware testing showed a repeatable small vertical jump correlated with
Print Shop changing from THINKING to PRINTING. Source tracing proved those
screen routines do not send printer data. The boundary is the greeting-card
`DUMP` routine.

Each DUMP historically performs:

```
CRLF X=7,Y=0
CRLF X=0,Y=1
... first raster row ...
```

With the compact R7 PRCOMS state machine, the first row of a new piece could
therefore receive an ordinary text LF instead of the native OkiGraph graphics
feed.

R8 leaves the proven R7 PRCOMS path intact and changes GCDRAW/DRAW1:

- explicitly enter OkiGraph graphics after the DUMP setup;
- on the first outside-card DUMP, skip the first-row vertical advance so
  raster output starts at the physical print-head position;
- on later pieces, perform one native `$03 $0E` graphics feed before the
  first row, matching ordinary in-piece band stepping.

The invalid ML92/93 `ESC % 9 n` sequence remains removed, and Print Shop's
1/36-inch LF36 helper remains suppressed.

## Known remaining dimensional issue

Print Shop's nominal seven-row band spacing is:

```
7/72 inch = 14/144 inch
```

The firmware-backed native OkiGraph graphics feed is:

```
15/144 inch
```

That difference predicts about 7.1% vertical stretch. R8 intentionally leaves
that measurable rather than sending an unsupported spacing command. A later
build can address scale by source-row resampling after the R8 piece-boundary
behavior is physically isolated.

## Distribution

The generated disk contains Brøderbund application resources and is not
committed to the repository. The transformation, compiler preparation,
validators, and disk builder are committed so a verified archive runtime can
reproduce the deterministic R8 image.
